## 1. 문제 정의·기획 (20)

- **화면이 주장을 증명해야 한다.** "직무를 고르면 졸업까지의 길이 그려진다"는 문장을 화면 문법으로 번역했다 — 노선도(트랙), 역(학기), 유도선(걸어온 길), 종착 게이트(직무), 검증 배지(보증).
- **시안 두 벌을 만들어 팀이 고르게 했다.** 3D 복도(스크롤 워크스루)와 2D 트랙을 모두 구현하고, 역할을 갈랐다 — 2D는 편집(스튜디오), 3D는 감상(걷기 모드). 같은 데이터·같은 캐릭터·같은 색.
- **접근성을 공익 앵글로.** 트랙 유도선을 점자블록 문법(gold)으로 그렸고 `prefers-reduced-motion`을 전 화면에서 존중한다.

### 2-2. 프롬프트 기록 — 사람이 무엇을 지시했나 (실제 발췌)

P3 세션의 실제 프롬프트를 유형별로 발췌한다. 화면 방향은 전부 사람이 정했고, AI는 구현·계측·검증을 맡았다.

| 유형 | 실제 프롬프트 | 결과 |
|---|---|---|
| 선행 검증 | "지금 이런 서비스를 진행하는 주제가 없어? **되게 민감한 문제니까 확인해.**" | 유사 서비스 3종 발견 → 1순위 아이디어 폐기. 이후 모든 아이디어에 선행 조사가 관례가 됨 |
| 컨셉 발상 | "스크롤을 내리면 **기차들이 지나가는 느낌**으로 진행하고 싶은데" | 3D 복도 → 행선판·노선도 은유가 서비스 전체 문법이 됨 |
| 브랜드 통제 | "전체적인 색감과 톤을 **명지전문대 홈페이지에 맞춰서**" | navy/sky/gold 토큰 실측 등록 — 하드코딩 금지 규칙 |
| 아키텍처 결정 | "#17 클로드로 결정하자" → "**필요할 때는 claude api 사용할거야, 원래는 사용 안 하고**" | LLM을 기본 경로가 아닌 옵트인으로 — 규칙 엔진 메인 구조의 방향 제시 |
| 관찰 → 수정 | (스크린샷 첨부) "지금 사람이 잘렸고", "왜 빈칸이 존재해", "'외 1'을 볼 수 있는 방법이 없잖아" | 픽셀 실측으로 원인 확정 후 수정 — 시안과 스크린샷이 대화의 기본 단위 |
| 인터랙션 설계 | "사람이 **저 칸으로 이동했다가** 저 내용이 떴으면 좋겠어" | 도착 기반 패널 — 두 단계 걷기(트랙→분기점) 구현 |
| 정보 구조 | "자격증은 자격증 따로, 학기는 학기별 전공 추천 따로" | CertPanel(gold)/SemesterPanel(navy) 분리 |
| 판단 교정 | "**왜 절반만 처리했어?**" | AI가 과하게 보류한 작업 범위를 사람이 되돌림 — 자격증 진단 절 즉시 구현 |

### 2-3. 검증 규율 — 눈이 아니라 계측

- 화면 주장은 전부 수치로 확인했다: 분기 이름표 겹침(전 학과 쌍 교차 검사 0건), 캐릭터 경로 이탈(rAF 샘플링 0px), 반응형(iframe 폭 강제 12조합, 푸터 뒤 여백 0), 화면-서버 근거 일치(125건 대조 0건 — 대조 스크립트를 저장소에 커밋).
- AI 산출물의 오류를 잡은 대표 사례: 파이썬 replace 패치가 대상 텍스트 변경으로 조용히 실패 → 이후 패치마다 grep 확인. Chromium이 foreignObject 안 offset-path에 viewBox 축척을 적용하지 않는 문제를 실측으로 확정 → HTML 오버레이로 우회.

## 4. 실용성 (20)

- 직무 미정 학생(추천 모드)·예비 입학생(학과 탐색)·재학생(이수 반영)·학교(트랙 B)를 한 화면 체계로.
- 현장실습·자격증은 실제 신청처(산학협력처·Q-Net)로 연결하되, 로그인 벽·리다이렉트를 실측해 안내 후 이동하게 했다.
