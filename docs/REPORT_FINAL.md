## 1. 문제 정의 및 기획성 (심사 20점)

### 1.1 수강신청 전날 밤

전문대 학생은 2~3년 안에 졸업요건·자격증·현장실습·취업을 **동시에** 끝내야 한다. 4년제와 달리 복구할 학기가 없다 — 1학년에 선수과목이나 자격증 타이밍을 한 번 놓치면 만회가 어렵다. 그런데 학생 손에 쥐어지는 정보는 **교육과정표 PDF 한 장**이다. "시스템 엔지니어가 되려면 어느 학기에 뭘 듣고 CCNA를 언제 따야 하는가"는 아무도 알려주지 않는다.

문제를 더 구체로 가르면 둘이다. **졸업요건**은 학사 편람에 있고(3년제 전공 66학점·교양필수·6학기), **취업 준비**는 학과 소개 페이지에 있다("이 학과를 나오면 이런 직업을"). **이 둘을 잇는 문서가 없다.** 학생은 "그 직무가 되려면 어느 학기에 무엇을 들어야 하고, 그렇게 들으면 졸업은 되는가"를 스스로 계산해야 한다.

### 1.2 기존 시스템과의 관계 — 대체가 아니라 상류 공정

학교 SMART CARE에도 "로드맵" 메뉴가 있다. 그러나 그것은 **학생이 직접 채워 등록하는 이력 관리 양식**이고, 문제는 학생이 그 빈칸에 뭘 넣을지 모른다는 것이다. 우리는 그 빈칸을 채워주는 엔진을 만들었다 — **우리 출력물이 SMART CARE의 입력물이 된다.** 학교 포털의 졸업사정 시뮬레이션이 "졸업 가능 여부의 **확인**"이라면, 우리는 목표 직무에서 역산한 "경로의 **설계**"다.

### 1.3 핵심 기획 판단 — 추천 근거를 학교 문서 안에서 찾았다

명지전문대 교육과정표에는 과목마다 **비고 열에 인재양성유형 라벨**이 붙어 있다 (`시스템관리·운용엔지니어` 등). 학교가 이미 "이 과목은 이 직무를 위한 것"이라고 적어 둔 것이다. 직무 역산을 **이 라벨로** 하고, NCS 직무기술서나 채용공고 크롤링을 쓰지 않았다.

| | 이 선택의 결과 |
|---|---|
| 설명가능성 | "왜 이 과목이냐"에 **학교 문서로** 답할 수 있다 |
| 검증가능성 | 심사위원이 교육과정표 원본과 대조할 수 있다 |
| 확장성 | 34개 학과에 같은 방식이 그대로 적용된다 |

### 1.4 두 개의 사용자 (트랙 A · 트랙 B)

같은 데이터로 두 사용자를 만족시킨다. **트랙 A(학생)**: 직무를 고르면 학기별 로드맵 + "졸업요건 충족 ✓" 판정. **트랙 B(학교)**: 학과가 홍보하는 진로와 교육과정이 실제로 라벨링한 직무를 대조한 정합도 리포트.

트랙 B는 부산물이 아니라 발견이다 — 실측하면 *정보통신공학과가 홍보하는 진로 6개 중 5개는 교육과정표에 대응 라벨이 없다.* 이것을 숨기지 않고 커버리지 0%와 사유를 그대로 내며, 학교가 교육과정을 개편할 때 쓸 수 있는 자료가 된다.

### 1.5 범위 통제

- **데모 시나리오 한 문장으로 범위를 고정했다** — "심사위원이 정보통신공학과와 `시스템관리·운용엔지니어`를 고르면 학기별 로드맵과 졸업요건 충족 배지가 뜨고, 검증기가 미달 로드맵을 잡아 재생성시키는 장면을 보여준다." 이 문장에 없는 기능은 만들지 않았다 (잘라낸 것: 소셜 로그인, 권한 등급, 수강신청 연동, 채용공고 크롤링).
- **컷 라인을 사전 합의했다** — 시각별로 무엇을 포기할지 시작할 때 정했고, 코어 데모가 부가 기능 때문에 깨지는 일을 금지했다.
- **화면이 주장을 증명하게 했다** (P3) — "직무를 고르면 졸업까지의 길이 그려진다"를 화면 문법으로 번역했다: 노선도(트랙), 역(학기), 점자블록 유도선(걸어온 길), 종착 게이트(직무), 검증 배지(보증). 유도선의 점자블록 문법과 `prefers-reduced-motion` 존중은 정보 접근성이라는 공익 앵글이기도 하다.

### 2.3 위임하지 않기로 한 결정 — 가장 중요한 판단

**처음 계획은 교육과정표 추출도 LLM에 맡기는 것이었다.** 그런데 35개 학과 PDF 헤더를 전수 확인하니 필수 5개 열 이름이 전부 같았다 — 코드로 읽으면 되는 일이었다. 추출을 코드로 옮기고 LLM은 폴백으로 강등했다(**발동 0회**). **검증기도 LLM을 쓰지 않는다** — 졸업 판정이 매번 달라지면 "졸업 보장"이 성립하지 않는다. LLM 예산은 판단이 필요한 한 곳(로드맵 배치와 근거 문장)에만 남겼고, 그마저 규칙 엔진과 비교 실측(응답 27초 vs 0.03초·재현성·근거 투명성) 후 **옵트인 비교 모드**로 내렸다.

### 2.4 제품 안의 AI — 환각이 검증기를 통과하지 못하게

```
LLM에게 주는 것:  후보 과목 목록 + 졸업요건 + 학기 상한
LLM이 고르는 것:  course_id 뿐
코드가 채우는 것:  과목명 · 학점 · 이수구분 (카탈로그에서)
```

카탈로그에 없는 `course_id`는 조용히 버려져 지어낸 과목이 응답에 도달하지 못하고(1차 방어), 결과를 검증기가 판정해 미달 사유로 재생성시킨다(2차 방어).

### 2.6 검증이 AI를 잡은 기록

**공통 교훈 — 초록불(테스트 통과)은 아무것도 증명하지 못한다.** 실데이터 전수 실행과 눈으로 찍어보기가 실제로 오류를 잡았다. 실패 사례 6건 전문은 `AI_USAGE.md`. 대표:

- **`__pycache__` 스테일 바이트코드가 변이 검사를 통째로 거짓으로** — 변이(`"교양"`→`"전공"`)가 UTF-8 바이트 길이가 같아 pyc 무효화(mtime+size)를 통과, 적용도 안 된 채 "10개 통과". 이후 변이 검사마다 캐시를 먼저 지운다.
- **리뷰가 테스트 2개를 무의미하다고 잡아냄** — 픽스처의 `careers`와 `talent_types`가 같은 문자열이라 불일치가 재현되지 않았다. 실데이터에서 갈라지는 조합으로 다시 썼다. *변이 검사가 없었으면 "11건 고치고 테스트 붙였다"고 보고했을 것이다.*
- **화면-서버 규칙 이원화** (P3) — 직무 매칭 규칙을 손으로 JS 포팅하면 또 갈라진다는 지적에, 전 학과 125건 대조 스크립트(`web/tools/check-jobmatch.mjs`)를 저장소에 커밋해 재발하면 잡히게 했다.
- **브라우저 렌더링의 거짓말** (P3) — Chromium이 foreignObject 안 offset-path에 viewBox 축척을 적용하지 않는 것을 실측(1.9배 어긋남)으로 확정하고 우회했다.

```
 직무 라벨 · 자격증)                                                │
                                                                    ▼
                                            loop.py ──► validator.py (순수 규칙)
                                             생성 → 검증 → 재생성 (상한 3)
                                                                    │
PostgreSQL ──► models.py                                            ▼
(유저 데이터 전용)                                    FastAPI (main.py) ──► React (web/)
```

**과목 데이터는 DB에 넣지 않는다.** `data/depts/*.json`이 유일한 소스, DB는 유저 데이터 전용이다. DB가 죽어도 코어(게스트 → 입력 → 로드맵)가 그대로 돈다. (데이터 아키텍처·테이블·CRUD 상세: README)

### 3.3 핵심 — 생성 → 검증 → 재생성 루프

기술적 주장은 하나다. **1차 생성 결과는 믿을 수 없다.** 그래서 생성기(무엇이든) 위에 졸업요건 검증기를 얹고 되먹임 루프를 돌린다. 미달 사유는 구조화해서 낸다:

```json
{ "rule": "major_credits", "label": "전공 학점",
  "required": 66, "actual": 51, "shortfall": 15,
  "fix": "전공 과목으로 15학점을 더 채우세요" }
```

`fix`가 그대로 재생성 프롬프트가 된다. 상한(3회)을 넘겨도 500이 아니라 **부분 로드맵 + 미달 사유를 200으로** 낸다 — 화면이 "여기까지 충족, 이것이 부족"을 그릴 수 있어야 한다.

**효과 (재현: `cd server && uv run python metrics.py`)**

```
시나리오 274개 (전 학과 × 목표 직무 × 재학 시점 2종)
  재생성 루프 OFF (1차 생성만)    41 / 274    15.0%
  재생성 루프 ON  (최대 3회)     272 / 274    99.3%
```

> "LLM 단독 15%"로 부르면 거짓이다 — 이 수치는 결정론적 규칙 생성기 기준, **"1차 생성 15.0%"** 가 정확하다.

**남은 미달 2건의 정체가 이 프로젝트의 백미다.** 드론정보공학과는 교육과정표의 전공을 전부 이수해도 43학점 — 요건 45에 2학점 모자란다(2026학년도 원본 PDF 재집계로 확정). 엔진의 실패가 아니라 **시스템이 찾아낸 학교 데이터의 실제 결손**이며, 트랙 B 리포트로 낸다.

### 3.4 추천 엔진 이중화 — 규칙 메인, LLM 옵트인

| | 규칙 (메인) | LLM (`MJC_ENGINE=llm`) |
|---|---|---|
| 응답 | **0.013초** | 32~45초 |
| 비용 | 0 | 조회당 발생 |
| 근거 | 데이터에 그대로 | 프롬프트 안 |
| 재현성 | 항상 같은 결과 | 매번 다름 |

둘 다 만들어 비교한 뒤 택했다. 어느 쪽이 돌았는지 응답 `engine` 필드로 항상 밝히고, LLM이 죽어도 규칙으로 떨어져 데모가 죽지 않는다. **직무 미정 모드**(배정 학점 1위 직무를 근거와 함께 추천)도 지원한다.

### 3.7 정직성 장치

심사에서 가장 위험한 것은 **동작하는 것처럼 보이지만 아닌 화면**이다. 어긋난 것을 응답과 화면에 남긴다: `engine`(폴백 은폐 방지) · `attempts`(검증기가 다시 짰다는 증거) · `job_match.note`(직무 대응 없음 고지 — 화면은 고르기 전에도 "교육과정 대응 없음" 표시) · `unknown_courses` · `remaining_credits`(판정 근거 없는 몫은 미달이 아니라 정보) · `extraction_confidence`(데이터 품질 공개) · 자격증 판정불가는 결손으로 세지 않음. **없는 과목을 지어내지 않는다.**

### 4.2 확장 경로와 운영 비용

- **타 대학 이식**: 파이프라인이 학과별 파서 없이 헤더 기반 — 같은 꼴의 교육과정표면 수집→추출→검증이 그대로 간다.
- **SMART CARE 연계**: 산출 로드맵이 기존 시스템의 입력이 되는 구조라 도입 마찰이 낮다.
- **운영 비용**: 메인 엔진이 규칙 기반이라 서버 외 비용 0. 키 만료·네트워크 장애에도 코어가 죽지 않는다.
- 다음 단계로 문서화한 것: 수강신청 연동(학사 권한 필요) · 자격증 일정 API · 졸업사정 공식 판정(편람 전 항목 필요).

### 4.3 한계를 밝힌다

- **교양선택·일반선택은 판정하지 않는다** — 교육과정표가 전공 전용 문서라 그 과목이 데이터에 없다. 지어내지 않고 `remaining_credits`로 알린다.
- **드론정보공학과는 통과 불가** — 실제 교육과정 공백이다.
- **공식 졸업사정이 아니다** — 판정 가능한 3개 룰에 대한 검증이며, 화면·푸터에 "실제 수강신청과 졸업 판정은 소속 학과 확인이 우선"을 명시했다.
