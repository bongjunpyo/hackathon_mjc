## 1. 문제 정의 및 기획 (심사: 문제 정의·기획성)

### 수강신청 전날 밤

전문대 학생은 2~3년 안에 졸업요건·자격증·현장실습·취업을 **동시에** 끝내야 한다. 4년제와 달리 복구할 학기가 없다 — 1학년에 선수과목이나 자격증 타이밍을 한 번 놓치면 만회가 어렵다. 그런데 학생 손에 쥐어지는 정보는 **교육과정표 PDF 한 장**이다. "시스템 엔지니어가 되려면 어느 학기에 뭘 듣고 CCNA를 언제 따야 하는가"는 아무도 알려주지 않는다. 이 정보격차는 신입생·편입생·직무를 아직 못 정한 학생에게 가장 크다.

### 기존 시스템과의 관계 — 대체가 아니라 상류 공정

학교 SMART CARE에도 "로드맵" 메뉴가 있다. 그러나 그것은 **학생이 직접 채워 등록하는 이력 관리 양식**이고, 문제는 학생이 그 빈칸에 뭘 넣을지 모른다는 것이다. 우리는 그 빈칸을 채워주는 엔진을 만들었다 — **우리 출력물이 SMART CARE의 입력물이 된다.** 학교 포털의 졸업사정 시뮬레이션이 "졸업 가능 여부의 **확인**"이라면, 우리는 목표 직무에서 역산한 "경로의 **설계**"다.

### 기획 원칙

- **데모 시나리오 한 문장으로 범위를 통제했다** — "심사위원이 학과와 직무를 고르면 학기별 로드맵과 졸업요건 충족 배지가 뜬다." 이 문장에 없는 기능은 만들지 않았고, 판단이 애매하면 이 문장으로 돌아왔다.
- **컷 라인을 사전 합의했다** — 시각별로 무엇을 포기할지 시작할 때 정했고(설계서 §8), 코어 데모가 부가 기능 때문에 깨지는 일을 금지했다.
- 20시간 안에 넣지 않기로 **판단한** 것들(채용공고 크롤링, NCS 원문 대조, 의미 매칭)을 "다음 단계"로 문서화했다 — 안 한 것과 못 한 것을 구분했다.

## 2. 기술 구현 (심사: 기술 구현 완성도)

### 아키텍처

```
                [브라우저 — React SPA]
                     │ fetch (단일 창구, 과목은 course_id로만)
                     ▼
┌──────────────── FastAPI ────────────────────┐
│ GET /depts·/report ──▶ data/*.json (읽기 전용) │
│ POST /roadmap ──▶ 추천 엔진(결정론 규칙)         │
│                    ⇄ 졸업요건 검증기 루프        │
│                    └ LLM 비교 모드(옵트인)      │
│ /auth·/me ──▶ PostgreSQL (유저 데이터 전용)     │
└─────────────────────────────────────────────┘
                     ▲
    [파이프라인] mjc.ac.kr 수집 → 추출 → 검증 → JSON
```

### 데이터 — 전 학과를 파이프라인 하나로

| 항목 | 결과 |
|---|---|
| 학과 | **34 / 35** (자유전공학과만 제외 — 과목 2개뿐) |
| 과목 | **842개** — 학년·학기·학점·이수구분·직무 라벨·NCS·현장중심 |
| 처리 경로 | **코드 파싱 100% · LLM 폴백 0회** (헤더 전수 확인 후 코드로 전환) |
| 과목 식별자 | 결정론 조립(NFKC·로마숫자 값 변환·괄호 보존) — 776과목 **충돌 0건** |

### 핵심 구조 — 생성은 엔진이, 판정은 검증기가

- **추천 엔진(메인)**: 실데이터 기반 결정론 규칙. 학교가 교육과정표에 부여한 과목↔직무 라벨로 역산한다. "왜 이 과목이냐"에 데이터로 답할 수 있고, 응답 0.1초, 언제나 같은 결과가 재현된다. **직무 미정 모드**(라벨 학점 1위 직무 추천)도 지원한다.
- **졸업요건 검증기**: 순수 규칙 코드(LLM 없음). 미달 항목마다 `{rule, label, required, actual, shortfall, fix}`를 내고, `fix` 문구가 그대로 재생성 입력이 된다(최대 3회).
- **LLM 에이전트(비교 검증)**: 같은 계약으로 Claude(`claude-sonnet-5`) 에이전트도 만들어 비교했다. 응답의 `engine` 필드가 어느 쪽이 짰는지 항상 밝힌다. 근거 투명성·재현성·응답 속도로 규칙 엔진을 메인에 놓았다.

### 정량 결과

| | |
|---|---|
| **검증기 효과** | **274개 시나리오: 1차 생성 15.0% → 루프 후 99.3%** (결정론 — `uv run python metrics.py`로 즉시 재현) |
| 테스트 | 160개 통과 · 변이 검사로 테스트 자체를 검증 |
| 재현성 | 새 폴더 clone → 설치 → 테스트 → 빌드 → API 전 경로 통과 확인. **API 키 없이 동작** |
| 인증 | JWT(액세스+리프레시) + 이메일 인증번호 가입 · 게스트 모드 항상 유지 |

**남은 미달 2건의 정체가 이 프로젝트의 백미다.** 드론정보공학과는 2026학년도 교육과정표의 전공을 전부 이수해도 43학점 — 공통 졸업요건 45학점에 2학점 모자란다(원본 PDF 재집계로 확정). 엔진의 실패가 아니라 **시스템이 찾아낸 학교 데이터의 실제 결손**이다.

## 3. AI 활용 (심사: AI 활용 역량)

### 3-1. 무엇으로 만들었나 — Claude Code 사용 구성

개발 전 과정을 **Claude Code(CLI)** 와의 페어 프로그래밍으로 진행했다. 20시간 단일 장기 세션(컨텍스트 요약으로 지속)으로 기획→설계→구현→검증→문서까지 이었다.

| 구성 | 사용한 것 | 어디에 |
|---|---|---|
| **모델** | Claude **Opus 5** (개발 세션 주력) · **Fable 5** (일부 구간) · **Sonnet 5** (제품 내 LLM 비교 모드) | 코딩·리뷰·조사 / 로드맵 LLM 에이전트 |
| **스킬** | `brainstorming` (superpowers 플러그인) | 최초 주제 선정 — 두 주제의 심사기준 배점 대비 판단 |
| | `claude-api` | LLM 에이전트(`agent.py`) 작성 — 구조화 출력·SDK 최신 패턴 |
| | `artifact-design` | 프론트 v2 확정 전, **클릭 가능한 화면 프로토타입**을 아티팩트로 제작해 팀 합의 |
| **MCP** | `playwright` (브라우저 자동화) | 3D 랜딩 시각 버그 진단, 화면 확인 |
| **내장 도구** | WebFetch / WebSearch | **할루시네이션 방지** — 졸업요건·NCS·자격증 정보를 학교/공공 원문에서 직접 확인하고 출처 URL과 함께 저장(`data/enrichment/evidence.json`) |
| **운영** | 백그라운드 프로세스(서버 기동·장기 측정), 병렬 도구 호출, `gh` CLI(이슈·PR 자동화) | 검증·리뷰 루프 |

### 3-2. 어떻게 통제했나 — 사람이 결정하고, AI가 만들고, 코드가 검증한다

- **폴더 소유권 + PR 리뷰**: AI가 만든 코드도 담당 폴더 밖이면 반드시 PR로 올려 담당자 리뷰를 받았다 (예: 서버 수정 PR에 "이견 있으면 되돌리셔도 됩니다" 명시). main 직push·force push 전면 금지.
- **위임 범위를 측정으로 정했다**: 교육과정표 추출을 LLM에 맡기려다, 35개 PDF 헤더를 전수 확인해 이름이 전부 같음을 보고 코드 파싱으로 전환했다. LLM은 폴백으로 강등(발동 0회).
- **실패를 기록했다**: AI 산출물에서 잡은 오류 6건을 `docs/AI_USAGE.md`에 위임 방식·검증 방법과 쌍으로 남겼다. 공통 교훈 — 초록불(테스트 통과)은 아무것도 증명하지 못하며, 실데이터 전수 실행과 눈으로 찍어보기가 실제로 오류를 잡았다.
- **아키텍처 결정도 비교 실험으로**: LLM 메인 → 규칙 메인 전환을 감으로 하지 않고, 두 엔진을 같은 계약으로 만들어 응답 시간(27초 vs 0.03초)·재현성·근거 투명성을 실측 비교한 뒤 팀이 결정했다.

### 3-3. 프롬프트 기록 (대표 사례)

전 과정의 프롬프트가 세션에 남아 있으며, 대표 사례를 유형별로 발췌한다:

| 유형 | 실제 프롬프트 (요지) | 결과 |
|---|---|---|
| 판단 요청 | "주제 2개와 심사 배점표를 줄 테니 **판단해달라**" | 배점 역산으로 주제 확정 |
| 사실 검증 | "학교 역량기반학사시스템에 비슷한 로드맵이 있대. **확인해줘**" | SMART CARE 분석 → "상류 공정" 포지셔닝 |
| 범위 통제 | "우선 깃허브는 건드리지 말고 참고만 해" / "PR 올리는 건 잠시 대기하자" | 접근 권한을 사람이 단계별로 부여 |
| 검증 지시 | "머지 전에 검증 한번 하자 — 문서 전부와 파일·트리 구조까지" | 교차 불일치 다수 발견·수정 |
| 반론 수용 | "LLM 대신 머신러닝을 쓰는 건 어때?" → AI의 반론(학습 데이터 부재) 청취 후 **"실데이터 기반 결정론"으로 재정의** | 심사 질의응답에 안전한 명명 |
| 원문 확인 | "(25·26년) 최신 기준으로 확인해줄래?" | 드론 43학점을 2026학년도 원본 PDF로 확정 |

### 3-4. 제품 안의 AI

로드맵 생성 LLM 에이전트(비교 모드)는 **환각 차단 2중 장치**로 설계했다: ① LLM은 카탈로그의 `course_id`만 고르고 학점·이수구분은 코드가 채운다(지어낼 여지 제거) ② 결과를 검증기가 판정하고 미달 사유로 재생성시킨다. 파이프라인의 LLM 폴백(헤더 파싱 실패 시)은 준비했으나 발동 0회였다.

## 4. 실용성 및 활용 가능성 (심사: 실용성·활용 가능성)

| 사용자 | 제공 가치 |
|---|---|
| 재학생 | 직무 역산 학기별 로드맵 + 자격증·이력서·포트폴리오 시점 + 졸업요건 실시간 검증 |
| **직무 미정 학생** | 학과 데이터 기반 직무 추천 → 추천 로드맵 (이 서비스가 가장 필요한 사용자를 내쫓지 않는다) |
| 예비 입학생 | 학과 탐색 — 34개 학과 커리큘럼·자격증·진로 열람 → 입학 전 로드맵 미리 그리기 |
| **학교 (트랙 B)** | 직무별 커버리지·자격증 결손·**졸업요건 불일치(드론 43/45)** 진단 리포트 — 교육과정 개편의 근거 자료 |

- **SMART CARE 연계**: 산출 로드맵이 기존 시스템의 입력이 되는 구조라 도입 마찰이 낮다.
- **확장성**: 파이프라인이 학과별 파서 없이 헤더 기반이라, 같은 꼴의 교과과정표를 쓰는 타 대학에 수집→추출→검증이 그대로 이식된다.
- **운영 비용**: 메인 엔진이 규칙 기반이라 서버 외 비용 0. 키 만료·네트워크 장애에도 코어가 죽지 않는다.

## 1. 문제 정의 및 기획성

### 1.1 문제

전문대 학생에게 "졸업"과 "취업"은 별개의 문제로 주어진다.

- **졸업요건**은 학사 편람에 있다 — 3년제 전공 66학점, 교양필수 3학점, 6학기 재학.
- **취업 준비**는 학과 소개 페이지에 있다 — "이 학과를 나오면 이런 직업을 가질 수 있다".

이 둘을 잇는 문서가 없다. 학생은 *"시스템 엔지니어가 되려면 어느 학기에 무엇을 들어야 하고, 그렇게 들으면 졸업은 되는가"* 를 스스로 계산해야 한다. 4년제와 달리 전문대는 여유 학점이 적어 **한 학기를 잘못 짜면 졸업이 밀린다.**

### 1.2 기획의 출발점 — 학교 문서 안에서 근거를 찾았다

이 프로젝트의 핵심 판단은 **추천 근거를 외부에서 가져오지 않은 것**이다.

명지전문대 교육과정표에는 과목마다 **비고 열에 인재양성유형 라벨**이 붙어 있다. `시스템관리·운용엔지니어`, `시스템응용SW개발엔지니어` 같은 값이다. 학교가 이미 "이 과목은 이 직무를 위한 것"이라고 적어 둔 것이다.

그래서 직무 역산을 **이 라벨로** 한다. NCS 직무기술서나 채용공고 크롤링을 쓰지 않았다.

| | 이 선택의 결과 |
|---|---|
| 설명가능성 | "왜 이 과목이냐"에 **학교 문서로** 답할 수 있다 |
| 검증가능성 | 심사위원이 교육과정표 원본과 대조할 수 있다 |
| 확장성 | 34개 학과에 같은 방식이 그대로 적용된다 |

### 1.3 두 개의 사용자 (트랙 A · 트랙 B)

같은 데이터로 두 사용자를 만족시킨다.

**트랙 A — 학생**: 직무를 고르면 학기별 로드맵 + "졸업요건 충족 ✓" 판정.

**트랙 B — 학교**: 학과가 **홍보하는 진로**(학과 소개 페이지)와 **교육과정이 실제로 라벨링한 직무**(교육과정표)를 대조한 정합도 리포트.

트랙 B는 부산물이 아니라 발견이다. 실측하면 이런 간극이 나온다.

```
정보통신공학과가 홍보하는 진로 6개 중 5개는
교육과정표에 대응하는 인재양성유형 라벨이 없다.
```

이것을 숨기지 않고 커버리지 0%와 사유를 그대로 낸다. 학교가 교육과정을 개편할 때 쓸 수 있는 자료다.

### 1.4 범위를 문장 하나로 고정했다

기획 단계에서 데모 시나리오를 한 문장으로 못 박고, **거기 등장하지 않는 기능은 만들지 않기로** 했다 (`CLAUDE.md`에 기록).

> 심사위원이 정보통신공학과와 목표 직무 `시스템관리·운용엔지니어`를 고르면 학기별 로드맵과 "졸업요건 충족 ✓" 배지가 뜨고, 검증기가 미달 로드맵을 잡아 재생성시키는 장면을 보여준다.

이 문장 덕에 잘라낸 것들: 소셜 로그인, 권한 등급, 수강신청 연동, 채용공고 크롤링, DB 마이그레이션 도구.

### 2.7 위임하지 않기로 한 결정 — 이게 가장 중요한 판단이다

**처음 계획은 교육과정표 추출도 LLM에 맡기는 것이었다.**

그런데 35개 학과 PDF의 헤더를 전수 확인하니 필수 5개 열(`교과목명`·`편성학년`·`편성학기`·`편성학점`·`이수구분`)의 **이름이 전부 같았다.** 코드로 읽으면 되는 일이었다.

| | 결과 |
|---|---|
| 처리 학과 | 34 / 35 (자유전공학과는 전공 미정으로 제외) |
| 처리 경로 | **코드 파싱 100% · LLM 폴백 0회** |
| 얻은 것 | 결정론(재실행해도 같은 결과) · 속도 · 비용 0 |

**검증기도 LLM을 쓰지 않는다.** 졸업 판정이 매번 달라지면 "졸업 보장"이 성립하지 않는다. 순수 규칙 코드다.

LLM 예산은 판단이 필요한 한 곳 — **로드맵 배치 순서와 근거 문장** — 에만 남겼다.

### 2.8 LLM을 제약한 방식 — 환각이 검증기를 통과하지 못하게

LLM에게 학점·이수구분까지 만들게 하면 **없는 과목이나 틀린 학점을 지어내고, 그 환각이 검증기를 통과할 수 있다.**

```
LLM에게 주는 것:  후보 과목 목록 + 졸업요건 + 학기 상한
LLM이 고르는 것:  course_id 뿐
코드가 채우는 것: 과목명 · 학점 · 이수구분 (카탈로그에서)
```

카탈로그에 없는 `course_id`는 **조용히 버린다.** 지어낸 과목은 응답에 도달하지 못한다.

### 2.9 검증 과정에서 잡아낸 오류 — 6건 (전문은 `AI_USAGE.md`)

> **여섯 건 모두 "초록불을 봤다"가 아무것도 증명하지 못한 사례다.** 하나의 교훈으로 묶인다 — **검증 도구 자체를 의심해야 한다.**

대표 2건:

**① `__pycache__` 스테일 바이트코드가 변이 검사를 통째로 거짓으로 만들었다.**
검증기 룰을 일부러 깨서 테스트가 잡는지 보는 중이었다. 마지막 변이가 `"교양"`→`"전공"`이라 **UTF-8 바이트 길이가 원본과 같았고**, Python의 pyc 무효화가 mtime+size 기반이라 변경을 놓쳤다. 변이가 적용되지 않은 채 "10개 통과"가 떴다. 이후 변이 검사마다 `__pycache__`를 먼저 지운다.

**② `python`이 Windows Store 스텁이어서 변이가 적용조차 안 됐다.**
스크립트가 `Python`만 출력하고 끝났는데 테스트는 초록불이었다. `uv run python`으로 바꿔 해결.

이 두 건 때문에 **"변이 검사 자체가 거짓말한다"** 는 걸 알게 됐고, 이후 모든 변이 검사에서 **변이가 실제로 적용됐는지 먼저 확인**한다.

### 2.10 최근 사례 — 리뷰가 제 테스트 2개를 무의미하다고 잡아냈다

코드 전체 리뷰에서 결함 11건을 재현하고 회귀 테스트를 붙인 뒤, 변이 검사를 돌렸다.

```
✅ 잡는다   검증기 중복 제거
✅ 잡는다   깨진 파일 건너뛰기
❌ 못 잡는다 report·roadmap 매핑 일치     ← 테스트가 무의미했다
❌ 못 잡는다 빈 학기 칸 생성              ← 테스트가 무의미했다
```

원인: 테스트 픽스처의 `careers`와 `talent_types`가 **같은 문자열**이라 불일치가 재현되지 않았다. 실데이터에서 갈라지는 조합으로 다시 써서 9/9를 만들었다.

**변이 검사가 없었으면 "11건 고치고 테스트 붙였다"고 보고했을 것이다.**

### 2.11 합칠 때 확인할 것

세 사람의 §2를 이어 붙일 때 세 가지만 맞추면 된다.

- **중복 제거** — 같은 스킬·MCP를 여러 사람이 썼으면 한 번만 적고, 누가 어디에 썼는지만 구분한다
- **모델 행 통합** — 사람마다 쓴 모델이 다르면(2.6 표) 행을 합치되 용도를 남긴다
- **층위 구분 유지(2.1)** — `Opus 5`(개발 도구)와 `claude-sonnet-5`(제품 런타임)를 섞지 않는다. 심사에서 "AI를 어디에 썼나"는 두 질문이고 답이 다르다

## 3. 기술 구현 완성도

### 3.1 아키텍처

```
data/depts/*.json  ──►  catalog.py  ──►  planner.py (규칙, 메인)  ──┐
(34개 학과, 전공                          agent.py  (LLM, 옵트인)  ──┤
 과목·라벨·자격증)                                                  │
                                                                    ▼
                                            loop.py ──► validator.py (순수 규칙)
                                             생성 → 검증 → 재생성 (상한 3)
                                                                    │
PostgreSQL ──► models.py                                            ▼
(유저 데이터 전용)                                    FastAPI (main.py) ──► React (web/)
```

**과목 데이터는 DB에 넣지 않는다.** `data/depts/*.json`이 유일한 소스다. DB는 유저 데이터 전용이다. 이렇게 하면 DB가 죽어도 코어(게스트 → 입력 → 로드맵)가 그대로 돈다.

### 3.2 핵심 — 생성 → 검증 → 재생성 루프

이 프로젝트의 기술적 주장은 하나다. **1차 생성 결과는 믿을 수 없다.**

```
생성기 ──► 검증기 ──► 미달?  ──► 미달 사유를 프롬프트로 되먹임 ──► 재생성
                       │                                              (상한 3회)
                       └─► 통과 ──► 응답
```

미달 사유는 사람이 읽는 문자열로 뭉개지 않고 **구조화해서** 낸다.

```json
{ "rule": "major_credits", "label": "전공 학점",
  "required": 66, "actual": 51, "shortfall": 15,
  "fix": "전공 과목으로 15학점을 더 채우세요" }
```

`fix`가 핵심이다. `shortfall: 15`만 주면 생성기가 아무 과목이나 채운다.

**상한을 넘겨도 500이 아니라 200을 낸다.** 부분 로드맵과 미달 사유를 함께 돌려줘야 화면이 "여기까지 충족, 이것이 부족"을 그릴 수 있다.

### 3.3 효과 측정 — 재현 가능한 지표

```
시나리오 274개 (전 학과 × 목표 직무 × 재학 시점 2종)

  재생성 루프 OFF (1차 생성만)    41 / 274    15.0%
  재생성 루프 ON  (최대 3회)     272 / 274    99.3%

  재생성 분포: 1회 41건 · 2회 231건 · 3회 2건
```

재현: `cd server && uv run python metrics.py`

> **"LLM 단독 15%"로 부르면 거짓이다.** 이 수치는 결정론적 규칙 생성기 기준이다 — **"1차 생성 15.0%"** 가 정확하다. 심사에서 "15%는 어느 모델입니까"에 답이 없는 표현을 쓰지 않는다.

남은 미달 2건은 **드론정보공학과**다. 개설 전공 과목이 43학점인데 요건이 45라 어떤 로드맵으로도 통과할 수 없다. **데이터 오류가 아니라 실제 교육과정 공백**이며, 이것도 리포트로 낸다.

### 3.4 추천 엔진 이중화 — 규칙 메인, LLM 옵트인

| | 규칙 (메인) | LLM (`MJC_ENGINE=llm`) |
|---|---|---|
| 응답 | **0.013초** | 32~45초 |
| 토큰 비용 | 0 | 조회당 발생 |
| 근거 | 데이터에 그대로 | 프롬프트 안 |
| 재현성 | 항상 같은 결과 | 매번 다름 |

둘 다 만들고 **비교한 뒤 규칙을 메인으로 택했다.** LLM은 삭제하지 않고 비교 데모용으로 남겼다. 어느 쪽이 돌았는지 응답의 `engine` 필드(`"rule"` / `"llm"` / `"rule (llm-failed)"`)로 **숨기지 않고** 밝힌다.

LLM이 죽어도(키 만료·레이트리밋·네트워크) 규칙으로 떨어져 **데모가 통째로 죽지 않는다.**

|---|---|
| 단위·통합 테스트 | **160 passed** |

### 3.6 정직성 장치

심사에서 가장 위험한 것은 **동작하는 것처럼 보이지만 아닌 화면**이다. 그래서 어긋난 것을 응답에 남긴다.

| 장치 | 왜 |
|---|---|
| `engine` | 폴백이 조용히 일어나면 규칙 결과를 LLM 결과로 오인한다 |
| `attempts` | 2 이상이면 검증기가 잡아 다시 짰다는 증거 |
| `job_match.note` | 직무 대응 라벨이 없으면 그 사실을 적는다 — 조용히 일반 로드맵을 주면 "직무 역산"이 거짓이 된다 |
| `unknown_courses` | 인식 못 한 `course_id`를 숨기지 않는다 |
| `remaining_credits` | 판정 근거가 없는 몫(교양선택·일반선택)은 미달로 잡지 않고 정보로 알린다 |
| `extraction_confidence` | 데이터 품질을 리포트에 함께 낸다 |

**없는 과목을 지어내지 않는다.** "일반선택 22학점" 블록을 깔면 화면은 채워지지만 학생은 무엇을 들을지 모른다.

## 4. 실용성 및 활용 가능성

### 4.1 지금 당장 쓸 수 있는 범위

- **34개 학과 전체** 대응. 특정 학과에 하드코딩된 것이 없다.
- **재학생 시점 반영** — 1학년 신입생부터 3학년 2학기까지, 이수한 과목을 빼고 남은 학기만 짠다.
- **직무 미정 학생** — 못 정했다고 내쫓지 않고, 배정 학점 1위 직무를 근거와 함께 추천한다.
- **게스트 모드** — 로그인 없이 전 기능. 학생이 바로 써 볼 수 있다.

### 4.2 학교 쪽 활용 (트랙 B)

교육과정 개편 회의에 그대로 올릴 수 있는 자료가 나온다.

| 리포트 항목 | 학교가 쓰는 방식 |
|---|---|
| 직무별 커버리지 | "이 진로를 홍보하는데 교과가 몇 학점 받쳐주는가" |
| 결손 진로 | 대응 라벨이 아예 없는 진로 목록 |
| 라벨 품질 4종 | 한 칸에 여러 직무 묶임 · 직무 아닌 값 · 오타로 갈린 라벨 · 순서만 다른 중복 표기 |
| 추출 신뢰도 | 데이터 품질을 함께 공개 |

실측: 34개 학과에서 **라벨 품질 문제 18건** 검출.

### 4.3 확장 경로

| 확장 | 필요한 것 |
|---|---|
| 다른 전문대 적용 | 교육과정표 형식만 맞추면 파이프라인 재사용. 학교별 하드코딩 없음 |
| 수강신청 연동 | 이번 범위에서 제외. 로드맵 → 실제 신청은 학사 시스템 권한 필요 |
| 자격증 일정 연동 | 시행기관 응시일정 API. 현재는 학과 안내 자격증을 학기에 배치하는 수준 |
| 졸업사정 공식 판정 | 학사 편람 전 항목(교양선택·일반선택 구성)이 필요. 현재는 판정 가능한 3개 룰만 |

### 4.4 한계를 밝힌다

- **교양선택·일반선택은 판정하지 않는다.** 교육과정표가 전공 전용 문서라 그 과목이 데이터에 없다. 지어내지 않고 `remaining_credits`로 "몇 학점 남았다"만 알린다.
- **드론정보공학과는 통과 불가.** 개설 전공 43학점 / 요건 45. 실제 교육과정 공백이다.
- **공식 졸업사정이 아니다.** 학사 편람 기준 3개 룰에 대한 판정이며 학교 공식 판정을 대체하지 않는다.

## 1. 문제 정의·기획 (20)

- **화면이 주장을 증명해야 한다.** "직무를 고르면 졸업까지의 길이 그려진다"는 문장을 화면 문법으로 번역했다 — 노선도(트랙), 역(학기), 유도선(걸어온 길), 종착 게이트(직무), 검증 배지(보증).
- **시안 두 벌을 만들어 팀이 고르게 했다.** 3D 복도(스크롤 워크스루)와 2D 트랙을 모두 구현하고, 역할을 갈랐다 — 2D는 편집(스튜디오), 3D는 감상(걷기 모드). 같은 데이터·같은 캐릭터·같은 색.
- **접근성을 공익 앵글로.** 트랙 유도선을 점자블록 문법(gold)으로 그렸고 `prefers-reduced-motion`을 전 화면에서 존중한다.

### 2-3. 검증 규율 — 눈이 아니라 계측

- 화면 주장은 전부 수치로 확인했다: 분기 이름표 겹침(전 학과 쌍 교차 검사 0건), 캐릭터 경로 이탈(rAF 샘플링 0px), 반응형(iframe 폭 강제 12조합, 푸터 뒤 여백 0), 화면-서버 근거 일치(125건 대조 0건 — 대조 스크립트를 저장소에 커밋).
- AI 산출물의 오류를 잡은 대표 사례: 파이썬 replace 패치가 대상 텍스트 변경으로 조용히 실패 → 이후 패치마다 grep 확인. Chromium이 foreignObject 안 offset-path에 viewBox 축척을 적용하지 않는 문제를 실측으로 확정 → HTML 오버레이로 우회.
