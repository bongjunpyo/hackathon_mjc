# AI 코딩 에이전트 활용 기록

> **원칙**: "AI로 만들었다"는 감점 요인으로 읽힌다. 역량으로 읽히는 것은
> **무엇을 왜 위임했고 그 결과를 어떻게 검증했는가**다. 아래 모든 기록을 그 쌍으로 남긴다.

## 사용 도구

| 도구 | 용도 | 사용자 |
|---|---|---|
| Claude Code (Opus 5) | `pipeline/` — 수집·추출 파이프라인, 트랙 B 진단, 문서 | P1 박효민 |
| Claude Code (Opus 5) | `server/` — 검증기·로드맵 생성기·API·인증 | P2 이동제 |
| Claude Code | `web/` — 화면 5개, 3D 랜딩 | P3 봉준표 |
| Claude API (`claude-sonnet-5`) | **제품 기능** — 로드맵 생성 에이전트 (`server/agent.py`) | — |

앞의 셋은 **개발 도구**이고, 마지막은 **제품이 호출하는 API**다. 서로 다른 층위다.

## 협업 구조

폴더 소유권(`pipeline` P1 / `server` P2 / `web` P3)을 그대로 **에이전트 경계**로 썼다. 각자 자기 폴더에서 독립적으로 에이전트를 돌리고, 경계는 **이슈와 PR 코멘트로만** 넘겼다. 담당 밖 파일은 문제를 발견해도 직접 고치지 않고 이슈로 올렸다 (#4 · #5 · #9 · #13 · #14 · #20 · #22 · #24 · #25).

그 결과 서로의 코드를 건드리지 않고도 계약 문제를 잡아냈다. 예를 들어 P3가 `lib/api.js`를 만들 때 서버는 아직 없었지만, 동결 스펙만 보고 양쪽이 따로 짠 뒤 대조해 어긋난 곳을 찾았다.

## 위임 범위를 측정으로 정했다

이 프로젝트에서 가장 중요한 판단이다. **처음에는 교육과정표 추출도 LLM에 맡길 계획이었다.**

그런데 35개 학과 PDF의 헤더를 전수 확인하니 필수 5개 열(`교과목명`·`편성학년`·`편성학기`·`편성학점`·`이수구분`)의 **이름이 전부 같았다.** 코드로 읽으면 되는 일이었다.

추출을 헤더 기반 파서로 옮기고 LLM은 헤더가 깨진 파일의 **폴백**으로 남겼다.

| | 결과 |
|---|---|
| 처리 학과 | 34 / 35 (자유전공학과는 전공 미정으로 제외) |
| 처리 경로 | **코드 파싱 100% · LLM 폴백 0회** |
| 얻은 것 | 결정론(재실행해도 같은 결과) · 속도 · 비용 0 |

LLM 예산은 판단이 필요한 곳 — **로드맵 생성 에이전트** — 에 집중시켰다. 목표 직무에서 역산해 학기별 계획을 짜고 자격증 취득 시점을 배치하는 일은 규칙 코드로 만들 수 없다.

## 작업별 위임과 검증

| 작업 | 위임 방식 | 검증 방법 | 결과 |
|---|---|---|---|
| 교육과정표 추출 | 스키마를 주고 파서 작성 위임 | 35개 학과 일괄 실행 + 원본 대조(정보통신공학과) | 35/35 표 추출 성공 |
| `course_id` 생성 | 규칙을 명세로 주고 구현 위임 | 전 학과 776과목 충돌 검사 | **충돌 2건 발견 → 수정** (사례 3) |
| 졸업요건 검증기 | 룰 표(설계서 §5)를 주고 **테스트 먼저** 작성하게 함 | **변이 검사 10종** — 룰을 하나씩 부수고 해당 테스트만 빨간불이 되는지 확인 | 전부 검출. 수정 없이 채택 |
| 재생성 루프 | LLM을 직접 부르지 않고 **생성기를 인자로 받게** 설계 지시 | 가짜 생성기로 1회 성공·2회째 성공·상한 초과 3케이스 | 채택 |
| 로드맵 에이전트 | 후보 목록에서 **`course_id`만 고르게** 제약 | 실제 API 호출로 2개 시나리오 생성 | **총학점 미달 발견 → 데이터 수정** (사례 5) |
| 직무 역산 생성기 | `talent_type` 라벨로 역산하도록 지시 | 34개 학과 실데이터 일괄 실행 | **직무를 바꿔도 결과가 같아** 설계 변경 (사례 4) |
| 트랙 B 라벨 진단 | 실데이터에서 발견한 4종 패턴을 케이스로 제시 | 34개 학과 전수 검사 → 18건 검출 | 채택 |
| 검증 효과 지표 | 시나리오 자동 생성 후 on/off 비교 | 152개 시나리오 실행 | **27.0% → 98.7%** |

### 로드맵 에이전트를 제약한 방식

LLM에게 학점·이수구분까지 만들게 하면 **없는 과목이나 틀린 학점을 지어내고, 그 환각이 검증기를 통과할 수 있다.** 후보 목록에서 `course_id`만 뽑게 하고 나머지 필드는 카탈로그에서 코드가 채운다. 카탈로그에 없는 id는 조용히 버려서 환각이 검증기까지 흘러가지 않는다.

## 검증 과정에서 잡아낸 오류

> **여섯 건 모두 "초록불을 봤다"가 아무것도 증명하지 못한 사례다.** 하나의 교훈으로 묶인다 — **검증 도구 자체를 의심해야 한다.**

### 사례 1 — `__pycache__` 스테일 바이트코드가 변이 검사를 통째로 거짓으로 만듦

- **에이전트가 내놓은 것**: 검증기 룰을 하나씩 무력화하고 테스트가 빨간불이 되는지 확인하는 변이 검사
- **어떻게 틀렸나**: 부등호 반전 변이가 2개 테스트만 깨뜨린 것으로 나왔다. 실제로는 10개 전부다
- **어떻게 발견했나**: 원본 복구 후에도 테스트가 계속 실패했다. 파일은 정상인데 결과가 이상해 추적했더니, 마지막 변이가 `"교양"`→`"전공"`이라 **UTF-8 바이트 길이가 원본과 같았고**, Python의 pyc 무효화가 mtime+size 기반이라 변경을 놓쳤다
- **최종 조치**: 변이 스크립트에 캐시 제거를 넣고 전체 재실행. 결과가 바뀌었다

### 사례 2 — `python`이 Windows Store 스텁이라 변이가 적용조차 안 됨

- **어떻게 틀렸나**: "10 passed"가 나와 검증된 줄 알았는데, **변이가 적용되지 않은 원본이 돌고 있었다**
- **어떻게 발견했나**: 출력 앞에 `Python`이라는 한 줄이 찍혀 있었다. 이 환경의 `python`은 Windows Store 스텁이라 heredoc이 실행되지 않고 그 문자열만 뱉는다
- **최종 조치**: `uv run python`으로 교체 후 재실행 — 2개 테스트가 정상적으로 빨간불이 됐다

### 사례 3 — 제안받은 `course_id` 규칙이 실데이터에서 충돌

- **에이전트가 내놓은 것**: 끝에 붙은 로마숫자를 `len()`으로 세어 아라비아 숫자로 바꾸는 함수
- **어떻게 틀렸나**: `IV`(4)를 글자 수 2로 계산한다. **`합주실기 II`와 `합주실기 IV`가 같은 id**가 된다
- **어떻게 발견했나**: 규칙을 그대로 쓰지 않고 전 학과 776과목에 적용해봤다. 실용음악과에서 3건 충돌
- **최종 조치**: 로마숫자를 값으로 변환하도록 교체. 함께 발견한 것 — 괄호를 지우면 `보육교사(인성)론` 같은 구분 정보가 사라져, 괄호 기호만 지우고 내용은 보존하도록 변경. **재검증 결과 충돌 0건**

### 사례 4 — 직무 역산이 작동하는 줄 알았으나 결과가 전부 같았음

- **어떻게 틀렸나**: 테스트는 통과했지만, 실제로 직무를 바꿔가며 출력을 찍어보니 **세 직무의 로드맵이 완전히 동일**했다
- **원인**: 재생성할 때 우선순위 티어를 통째로 열어서, 3차에는 어떤 직무든 모든 선택과목을 담게 된다. 게다가 전문대 교육과정은 여유 학점이 적어 구조적으로 선택의 폭이 좁다
- **최종 조치**: 티어를 통째로 열지 않고 **모자란 만큼만** 채우도록 변경. 다만 여유 학점이 적다는 사실은 그대로라, 과목 집합이 수렴하는 것을 감추지 않고 `job_related` 플래그로 **무엇이 직무 때문에 들어갔는지**를 표시하는 방향으로 정직하게 물러섰다

### 사례 5 — 32개 학과가 구조적으로 졸업 불가능이었음

- **어떻게 틀렸나**: 단위 테스트도, 규칙 기반 생성기도 통과했다. **실제 LLM으로 로드맵을 생성해 검증기에 걸어보고서야** 3회 재생성 후에도 88/110으로 실패하는 것을 봤다
- **원인**: 교육과정표는 전공과 교양필수만 싣는다. 선택 학점 버킷을 "교양 최소치 − 필수"(7학점)로만 계산해서, **교육과정표 과목을 전부 들어도 총학점에 도달하지 못했다.** 34개 중 32개 학과가 그랬다
- **최종 조치**: 버킷을 **총학점 기준**으로 재계산(정보통신공학과 7 → 29학점). 졸업요건 충족 가능 학과 2 → 33
- **남은 1곳**: 드론정보공학과는 전공 43/45로 전공 학점 자체가 모자라 버킷으로 해결되지 않는다. 교육과정 원본의 공백이라 숨기지 않고 품질 지표(`data/depts/_report.json`)에 남겼다

### 사례 6 — 파서를 고치다 멀쩡하던 학과를 오염시킴

- **무엇을 했나**: 드론정보공학과 자격증이 0개로 나와, 절 제목 표기 변형(`취득가능 자격증`)을 파서에 추가
- **어떻게 틀렸나**: 드론은 13개로 복구됐는데 **정보통신공학과가 16개 → 21개로 늘고 내용이 오염**됐다. `"과정 및 전공영어 교육으로 국내"` 같은 문장 조각이 자격증으로 들어왔다
- **원인**: 느슨한 표기(`자격증 취득`)를 후보에 넣었더니, 교육목표 본문의 *"…국가 공인 및 국제 공인 **자격증 취득**과정 및 전공영어 교육으로…"* 가 실제 절 제목보다 **페이지 앞쪽**에 있어 위치 기준 매칭에서 이겼다
- **어떻게 발견했나**: 고친 학과만 보지 않고 다른 학과 결과를 함께 출력해 비교했다
- **최종 조치**: 위치가 아니라 **목록 순서**(구체적 표기 우선) 기준으로 변경

## 사람이 직접 작성한 부분

- **판단이 필요한 설계 결정** — 총학점을 미달로 잡을지 "남은 학점"으로 알릴지, 이메일 인증에서 JWT를 URL에 싣지 않는 방식(1회용 교환 코드), 추출에 LLM을 쓸지 코드로 갈지
- **위임 범위의 결정 자체** — 헤더 일관성을 측정한 뒤 "여기는 코드, 저기는 LLM"을 가른 것
- **다른 담당자에게 넘길 것과 직접 고칠 것의 구분** — 폴더 경계
- 픽스처 데이터 설계, 프롬프트 제약 설계(`course_id`만 고르게 하기)

## 회고

에이전트는 코드를 빠르게 만들지만 **자기가 만든 검증이 진짜인지는 확인해주지 않는다.** 위 여섯 건이 전부 그 지점이다 — 테스트는 초록불이었고, 변이 검사라는 2차 장치를 붙였는데 그 2차 장치마저 세 번 거짓말을 했다.

실제로 효과가 있었던 것은 **"결과를 눈으로 찍어보기"** 였다.

- 직무별 로드맵을 출력해보고 나서야 세 직무의 결과가 전부 같다는 것을 알았다 (사례 4)
- 34개 학과에 일괄 실행하고 나서야 32개가 졸업 불가능이라는 것을 알았다 (사례 5)
- 규칙을 그대로 쓰지 않고 776과목에 적용해보고서야 `IV`와 `II`가 충돌한다는 것을 알았다 (사례 3)
- 고친 학과만 보지 않고 다른 학과와 비교해보고서야 오염을 발견했다 (사례 6)

**단위 테스트는 그 어느 것도 잡지 못했다.**
