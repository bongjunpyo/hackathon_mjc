### 안건 2 — 스키마·API 동결 (가장 급함, 회의 후 1시간 내)
설계서 §5의 `courses.json` 스키마와 API 스펙을 훑고 동결한다. 동결 후 변경은 3인 합의로만.

> **동결 전 검토 의견 (사전 리뷰)** — 아래 3건은 동결에 반드시 포함, 4건은 여유 되면. 근거: 사전 검증 노트(팀 옵시디언)

**반드시 넣을 것 (동결 누락 시 나중에 비싸게 물어야 함)**

1. **`course_id` 신설 — 과목명 문자열 매칭 금지**
   현재 `POST /roadmap`의 `completed_courses: [name]`은 과목명 문자열로 주고받는다. 교육과정표 원본에는 로마숫자 `Ⅰ`(U+2160)·라틴 `I`·아라비아 `1`이 섞여 있고 공백/괄호 표기도 학과마다 다르다. **HWP 추출본과 프론트 체크박스가 한 글자만 어긋나도 검증기가 "미이수"로 판정**한다 — 데모 중 터지기 가장 쉬운 지점.
   → `courses[]`에 `course_id`(예: `itc-1-1-prog1`) 추가, API는 id로만 주고받기. 표시용 `name`은 그대로 유지.

2. **`validation.details`를 구조화 배열로**
   지금은 `details` 한 덩어리. 그런데 self-correction 루프가 기술점수의 핵심 소재이므로, **LLM 재생성 프롬프트에 그대로 꽂을 수 있는 형태**여야 하고 발표 화면에도 띄워야 한다.
   → `details: [{ rule: "major_credits", required: 66, actual: 60, shortfall: 6 }, ...]`
   이 배열이 곧 재생성 프롬프트이자 시연 장면이다.

3. **재생성 루프 상한을 API 계약에 명시**
   검증 실패 → 재생성이 무한히 돌면 시연 중 응답이 안 온다.
   → `max_retries: 3`, 초과 시 `validation.passed: false` + 부분 로드맵 + 미달 사유를 **정상 응답으로** 반환 (에러 아님). 화면은 "여기까지 충족, 이것이 부족" 상태를 그릴 수 있어야 함.

**여유 되면**

4. `target_job`은 자유 문자열 대신 `careers[]`에서 고른 값 (임베딩 매칭 결과가 매번 달라지는 것 방지). 선택지는 `GET /depts` 응답에 포함하거나 `GET /jobs?dept_id=` 신설
5. `GET /report/{dept_id}` 응답에 `tier`, `extraction_confidence` 포함 — Tier 2 학과 리포트에 신뢰도가 안 드러나면 "정직한 공개"가 성립 안 됨
6. 에러 응답 형식 1개 동결 (`{ error: { code, message } }`) — 없으면 P3가 에러 UI를 목데이터로 못 만듦
7. `category`에 `교양필수` 구분이 `required` 플래그로 충분한지 확인 (인성채플·성경과삶 검증에 필요)

- **`ncsi.mjc.ac.kr` (역량기반 학사시스템) 로그인 실사용 확인 완료.** 기능은 ① MJC-ACT/AIM 역량 안내(정적) ② 수업관리(이미 등록한 과목의 강의계획서·강의평가·성적 조회) ③ 만족도 설문 — **직무 로드맵·졸업요건 검증·자격증 추천 기능 없음.** 전부 사후 조회 도구.
  → 심사 질문 대응: *"그 시스템은 이미 들은 과목을 조회하는 도구고, 저희는 아직 안 들은 과목을 목표 직무에서 역산해 설계합니다."*
- `inno.mjc.ac.kr` SMART CARE "데이터 기반 맞춤형 로드맵"은 **상담·비교과 프로그램**(지도교수 진로지도, 특강, 진단검사) 중심 → 층위 다름. 다만 발표에서 언급될 수 있으니 P3가 문장 하나 준비.
