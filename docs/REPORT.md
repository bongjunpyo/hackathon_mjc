## 1. 문제 정의 및 기획성

### 1.1 문제

전문대 학생에게 "졸업"과 "취업"은 별개의 문제로 주어진다.

- **졸업요건**은 학사 편람에 있다 — 3년제 전공 66학점, 교양필수 3학점, 6학기 재학.
- **취업 준비**는 학과 소개 페이지에 있다 — "이 학과를 나오면 이런 직업을 가질 수 있다".

이 둘을 잇는 문서가 없다. 학생은 *"시스템 엔지니어가 되려면 어느 학기에 무엇을 들어야 하고, 그렇게 들으면 졸업은 되는가"* 를 스스로 계산해야 한다. 4년제와 달리 전문대는 여유 학점이 적어 **한 학기를 잘못 짜면 졸업이 밀린다.**

### 1.2 기획의 출발점 — 학교 문서 안에서 근거를 찾았다

이 프로젝트의 핵심 판단은 **추천 근거를 외부에서 가져오지 않은 것**이다.

명지전문대 교육과정표에는 과목마다 **비고 열에 인재양성유형 라벨**이 붙어 있다. `시스템관리·운용엔지니어`, `시스템응용SW개발엔지니어` 같은 값이다. 학교가 이미 "이 과목은 이 직무를 위한 것"이라고 적어 둔 것이다.

그래서 직무 역산을 **이 라벨로** 한다. NCS 직무기술서나 채용공고 크롤링을 쓰지 않았다.

| | 이 선택의 결과 |
|---|---|
| 설명가능성 | "왜 이 과목이냐"에 **학교 문서로** 답할 수 있다 |
| 검증가능성 | 심사위원이 교육과정표 원본과 대조할 수 있다 |
| 확장성 | 34개 학과에 같은 방식이 그대로 적용된다 |

### 1.3 두 개의 사용자 (트랙 A · 트랙 B)

같은 데이터로 두 사용자를 만족시킨다.

**트랙 A — 학생**: 직무를 고르면 학기별 로드맵 + "졸업요건 충족 ✓" 판정.

**트랙 B — 학교**: 학과가 **홍보하는 진로**(학과 소개 페이지)와 **교육과정이 실제로 라벨링한 직무**(교육과정표)를 대조한 정합도 리포트.

트랙 B는 부산물이 아니라 발견이다. 실측하면 이런 간극이 나온다.

```
정보통신공학과가 홍보하는 진로 6개 중 5개는
교육과정표에 대응하는 인재양성유형 라벨이 없다.
```

이것을 숨기지 않고 커버리지 0%와 사유를 그대로 낸다. 학교가 교육과정을 개편할 때 쓸 수 있는 자료다.

### 1.4 범위를 문장 하나로 고정했다

기획 단계에서 데모 시나리오를 한 문장으로 못 박고, **거기 등장하지 않는 기능은 만들지 않기로** 했다 (`CLAUDE.md`에 기록).

> 심사위원이 정보통신공학과와 목표 직무 `시스템관리·운용엔지니어`를 고르면 학기별 로드맵과 "졸업요건 충족 ✓" 배지가 뜨고, 검증기가 미달 로드맵을 잡아 재생성시키는 장면을 보여준다.

이 문장 덕에 잘라낸 것들: 소셜 로그인, 권한 등급, 수강신청 연동, 채용공고 크롤링, DB 마이그레이션 도구.

## 2. AI 활용 역량

> **원칙**: "AI로 만들었다"는 그 자체로 역량이 아니다. 역량으로 읽히는 것은 **무엇을 왜 위임했고, 그 결과를 어떻게 검증했는가**다. 이 절의 모든 기록은 그 쌍으로 남긴다.
>
> 상세 기록은 [`docs/AI_USAGE.md`](AI_USAGE.md) — 위임·검증 쌍 8건과 **실패 사례 6건**이 있다.

> ### ⬜ 이 절의 2.2 ~ 2.6은 **P2(이동제) 세션 기준**이다
>
> 모드·스킬·MCP·플러그인·모델 기록은 **`server/` 작업에서 실제로 쓴 것만** 적었다. 추측으로 채우지 않았다.

### 2.7 위임하지 않기로 한 결정 — 이게 가장 중요한 판단이다

**처음 계획은 교육과정표 추출도 LLM에 맡기는 것이었다.**

그런데 35개 학과 PDF의 헤더를 전수 확인하니 필수 5개 열(`교과목명`·`편성학년`·`편성학기`·`편성학점`·`이수구분`)의 **이름이 전부 같았다.** 코드로 읽으면 되는 일이었다.

| | 결과 |
|---|---|
| 처리 학과 | 34 / 35 (자유전공학과는 전공 미정으로 제외) |
| 처리 경로 | **코드 파싱 100% · LLM 폴백 0회** |
| 얻은 것 | 결정론(재실행해도 같은 결과) · 속도 · 비용 0 |

**검증기도 LLM을 쓰지 않는다.** 졸업 판정이 매번 달라지면 "졸업 보장"이 성립하지 않는다. 순수 규칙 코드다.

LLM 예산은 판단이 필요한 한 곳 — **로드맵 배치 순서와 근거 문장** — 에만 남겼다.

### 2.8 LLM을 제약한 방식 — 환각이 검증기를 통과하지 못하게

LLM에게 학점·이수구분까지 만들게 하면 **없는 과목이나 틀린 학점을 지어내고, 그 환각이 검증기를 통과할 수 있다.**

```
LLM에게 주는 것:  후보 과목 목록 + 졸업요건 + 학기 상한
LLM이 고르는 것:  course_id 뿐
코드가 채우는 것: 과목명 · 학점 · 이수구분 (카탈로그에서)
```

카탈로그에 없는 `course_id`는 **조용히 버린다.** 지어낸 과목은 응답에 도달하지 못한다.

### 2.9 검증 과정에서 잡아낸 오류 — 6건 (전문은 `AI_USAGE.md`)

> **여섯 건 모두 "초록불을 봤다"가 아무것도 증명하지 못한 사례다.** 하나의 교훈으로 묶인다 — **검증 도구 자체를 의심해야 한다.**

대표 2건:

**① `__pycache__` 스테일 바이트코드가 변이 검사를 통째로 거짓으로 만들었다.**
검증기 룰을 일부러 깨서 테스트가 잡는지 보는 중이었다. 마지막 변이가 `"교양"`→`"전공"`이라 **UTF-8 바이트 길이가 원본과 같았고**, Python의 pyc 무효화가 mtime+size 기반이라 변경을 놓쳤다. 변이가 적용되지 않은 채 "10개 통과"가 떴다. 이후 변이 검사마다 `__pycache__`를 먼저 지운다.

**② `python`이 Windows Store 스텁이어서 변이가 적용조차 안 됐다.**
스크립트가 `Python`만 출력하고 끝났는데 테스트는 초록불이었다. `uv run python`으로 바꿔 해결.

이 두 건 때문에 **"변이 검사 자체가 거짓말한다"** 는 걸 알게 됐고, 이후 모든 변이 검사에서 **변이가 실제로 적용됐는지 먼저 확인**한다.

### 2.10 최근 사례 — 리뷰가 제 테스트 2개를 무의미하다고 잡아냈다

코드 전체 리뷰에서 결함 11건을 재현하고 회귀 테스트를 붙인 뒤, 변이 검사를 돌렸다.

```
✅ 잡는다   검증기 중복 제거
✅ 잡는다   깨진 파일 건너뛰기
❌ 못 잡는다 report·roadmap 매핑 일치     ← 테스트가 무의미했다
❌ 못 잡는다 빈 학기 칸 생성              ← 테스트가 무의미했다
```

원인: 테스트 픽스처의 `careers`와 `talent_types`가 **같은 문자열**이라 불일치가 재현되지 않았다. 실데이터에서 갈라지는 조합으로 다시 써서 9/9를 만들었다.

**변이 검사가 없었으면 "11건 고치고 테스트 붙였다"고 보고했을 것이다.**

```
data/depts/*.json  ──►  catalog.py  ──►  planner.py (규칙, 메인)  ──┐
(34개 학과, 전공                          agent.py  (LLM, 옵트인)  ──┤
 과목·라벨·자격증)                                                  │
                                                                    ▼
                                            loop.py ──► validator.py (순수 규칙)
                                             생성 → 검증 → 재생성 (상한 3)
                                                                    │
PostgreSQL ──► models.py                                            ▼
(유저 데이터 전용)                                    FastAPI (main.py) ──► React (web/)
```

**과목 데이터는 DB에 넣지 않는다.** `data/depts/*.json`이 유일한 소스다. DB는 유저 데이터 전용이다. 이렇게 하면 DB가 죽어도 코어(게스트 → 입력 → 로드맵)가 그대로 돈다.

### 3.2 핵심 — 생성 → 검증 → 재생성 루프

이 프로젝트의 기술적 주장은 하나다. **1차 생성 결과는 믿을 수 없다.**

```
생성기 ──► 검증기 ──► 미달?  ──► 미달 사유를 프롬프트로 되먹임 ──► 재생성
                       │                                              (상한 3회)
                       └─► 통과 ──► 응답
```

미달 사유는 사람이 읽는 문자열로 뭉개지 않고 **구조화해서** 낸다.

```json
{ "rule": "major_credits", "label": "전공 학점",
  "required": 66, "actual": 51, "shortfall": 15,
  "fix": "전공 과목으로 15학점을 더 채우세요" }
```

`fix`가 핵심이다. `shortfall: 15`만 주면 생성기가 아무 과목이나 채운다.

**상한을 넘겨도 500이 아니라 200을 낸다.** 부분 로드맵과 미달 사유를 함께 돌려줘야 화면이 "여기까지 충족, 이것이 부족"을 그릴 수 있다.

### 3.3 효과 측정 — 재현 가능한 지표

```
시나리오 274개 (전 학과 × 목표 직무 × 재학 시점 2종)

  재생성 루프 OFF (1차 생성만)    41 / 274    15.0%
  재생성 루프 ON  (최대 3회)     272 / 274    99.3%

  재생성 분포: 1회 41건 · 2회 231건 · 3회 2건
```

재현: `cd server && uv run python metrics.py`

> **"LLM 단독 15%"로 부르면 거짓이다.** 이 수치는 결정론적 규칙 생성기 기준이다 — **"1차 생성 15.0%"** 가 정확하다. 심사에서 "15%는 어느 모델입니까"에 답이 없는 표현을 쓰지 않는다.

남은 미달 2건은 **드론정보공학과**다. 개설 전공 과목이 43학점인데 요건이 45라 어떤 로드맵으로도 통과할 수 없다. **데이터 오류가 아니라 실제 교육과정 공백**이며, 이것도 리포트로 낸다.

### 3.4 추천 엔진 이중화 — 규칙 메인, LLM 옵트인

| | 규칙 (메인) | LLM (`MJC_ENGINE=llm`) |
|---|---|---|
| 응답 | **0.013초** | 32~45초 |
| 토큰 비용 | 0 | 조회당 발생 |
| 근거 | 데이터에 그대로 | 프롬프트 안 |
| 재현성 | 항상 같은 결과 | 매번 다름 |

둘 다 만들고 **비교한 뒤 규칙을 메인으로 택했다.** LLM은 삭제하지 않고 비교 데모용으로 남겼다. 어느 쪽이 돌았는지 응답의 `engine` 필드(`"rule"` / `"llm"` / `"rule (llm-failed)"`)로 **숨기지 않고** 밝힌다.

LLM이 죽어도(키 만료·레이트리밋·네트워크) 규칙으로 떨어져 **데모가 통째로 죽지 않는다.**

### 3.5 검증 실적

| 검증 | 결과 |
|---|---|
| 단위·통합 테스트 | **153 passed** |
| 변이 검사 | 룰을 일부러 깨면 해당 테스트만 실패하는지 확인 |
| 실데이터 | 34개 학과 · **직무 조합 172개 전부 200** (404·400 0건) |
| 실 PostgreSQL | **13/13** — 가입→인증→교환코드→로그인→이수내역 왕복 |
| 실 Claude API | 32~45초 · `engine=llm` · `passed=True` |
| 프론트↔백엔드 | 화면이 제공하는 모든 학과·직무 조합을 실제로 POST해 대조 |

### 3.6 정직성 장치

심사에서 가장 위험한 것은 **동작하는 것처럼 보이지만 아닌 화면**이다. 그래서 어긋난 것을 응답에 남긴다.

| 장치 | 왜 |
|---|---|
| `engine` | 폴백이 조용히 일어나면 규칙 결과를 LLM 결과로 오인한다 |
| `attempts` | 2 이상이면 검증기가 잡아 다시 짰다는 증거 |
| `job_match.note` | 직무 대응 라벨이 없으면 그 사실을 적는다 — 조용히 일반 로드맵을 주면 "직무 역산"이 거짓이 된다 |
| `unknown_courses` | 인식 못 한 `course_id`를 숨기지 않는다 |
| `remaining_credits` | 판정 근거가 없는 몫(교양선택·일반선택)은 미달로 잡지 않고 정보로 알린다 |
| `extraction_confidence` | 데이터 품질을 리포트에 함께 낸다 |

**없는 과목을 지어내지 않는다.** "일반선택 22학점" 블록을 깔면 화면은 채워지지만 학생은 무엇을 들을지 모른다.

## 4. 실용성 및 활용 가능성

### 4.1 지금 당장 쓸 수 있는 범위

- **34개 학과 전체** 대응. 특정 학과에 하드코딩된 것이 없다.
- **재학생 시점 반영** — 1학년 신입생부터 3학년 2학기까지, 이수한 과목을 빼고 남은 학기만 짠다.
- **직무 미정 학생** — 못 정했다고 내쫓지 않고, 배정 학점 1위 직무를 근거와 함께 추천한다.
- **게스트 모드** — 로그인 없이 전 기능. 학생이 바로 써 볼 수 있다.

### 4.2 학교 쪽 활용 (트랙 B)

교육과정 개편 회의에 그대로 올릴 수 있는 자료가 나온다.

| 리포트 항목 | 학교가 쓰는 방식 |
|---|---|
| 직무별 커버리지 | "이 진로를 홍보하는데 교과가 몇 학점 받쳐주는가" |
| 결손 진로 | 대응 라벨이 아예 없는 진로 목록 |
| 라벨 품질 4종 | 한 칸에 여러 직무 묶임 · 직무 아닌 값 · 오타로 갈린 라벨 · 순서만 다른 중복 표기 |
| 추출 신뢰도 | 데이터 품질을 함께 공개 |

실측: 34개 학과에서 **라벨 품질 문제 18건** 검출.

### 4.3 확장 경로

| 확장 | 필요한 것 |
|---|---|
| 다른 전문대 적용 | 교육과정표 형식만 맞추면 파이프라인 재사용. 학교별 하드코딩 없음 |
| 수강신청 연동 | 이번 범위에서 제외. 로드맵 → 실제 신청은 학사 시스템 권한 필요 |
| 자격증 일정 연동 | 시행기관 응시일정 API. 현재는 학과 안내 자격증을 학기에 배치하는 수준 |
| 졸업사정 공식 판정 | 학사 편람 전 항목(교양선택·일반선택 구성)이 필요. 현재는 판정 가능한 3개 룰만 |

### 4.4 한계를 밝힌다

- **교양선택·일반선택은 판정하지 않는다.** 교육과정표가 전공 전용 문서라 그 과목이 데이터에 없다. 지어내지 않고 `remaining_credits`로 "몇 학점 남았다"만 알린다.
- **드론정보공학과는 통과 불가.** 개설 전공 43학점 / 요건 45. 실제 교육과정 공백이다.
- **공식 졸업사정이 아니다.** 학사 편람 기준 3개 룰에 대한 판정이며 학교 공식 판정을 대체하지 않는다.

### 5.1 저장소 운영

| | |
|---|---|

**한 방 커밋이 없다.** 작업 단위 브랜치 → PR → 리뷰 → 머지를 지켰다. 히스토리 자체가 개발 과정의 증거다.

### 5.2 폴더 소유권을 에이전트 경계로 썼다

```
pipeline/ data/  →  P1 박효민
server/         →  P2 이동제
web/            →  P3 봉준표
docs/           →  P1 겸임
```

각자 자기 폴더에서 독립적으로 에이전트를 돌리고, **경계는 이슈와 PR 코멘트로만** 넘겼다. 담당 밖 파일은 문제를 발견해도 직접 고치지 않고 이슈로 올렸다.

그 결과 서로의 코드를 건드리지 않고도 계약 문제를 잡았다. 예: 프론트가 `lib/api.js`를 만들 때 서버는 아직 없었지만, 동결 스펙만 보고 양쪽이 따로 짠 뒤 대조해 어긋난 곳을 찾았다.

### 5.3 리뷰가 실제로 작동했다

PR 리뷰가 형식이 아니었다는 증거:

| 리뷰에서 잡힌 것 | 결과 |
|---|---|
| 검증기가 이수 과목을 무시 | 2학년 학생이 어떤 로드맵으로도 통과 못 하는 상태였다 → 수정 |
| 검증기가 LLM 형식 오류에 죽음 | `KeyError: 'credits'` → 형식 검사 룰 추가 |
| `GET /depts` 500 | 추출 리포트 파일을 학과로 읽음 → 수정 |
| 중복 `course_id`로 학점 부풀림 | 같은 id 5번에 전공 54→66학점(요건선) → 이중 방어 |
| `.env` 값이 무시됨 | JWT가 커밋된 기본키로 서명되고 있었다 → import 순서 수정 |
| 두 엔진의 응답 모양이 다름 | 규칙 폴백일 때 프론트가 `undefined`를 받았다 → 계약 일치 |
