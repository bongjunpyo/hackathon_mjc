# CLAUDE.md — 프론트엔드 (동제)

루트 `CLAUDE.md`의 공통 계약이 먼저다. 이 문서는 그 위에 얹는 담당 규칙이다.

## 담당

`index.html`, `style.css`, `js/ui/ui.js` — 화면 전부.

**세 명 중 유일하게 루트 파일을 건드린다.** `index.html`은 세 명 다 script 태그나 버튼을 넣고 싶어하는
파일이라 충돌 위험이 가장 높다. **뼈대를 가장 먼저 만들어 올려야** 나머지 두 명이 기다리지 않는다.

## 가장 먼저 할 일

`index.html` 뼈대 + script 태그 3개를 만들어 **10분 안에 커밋한다.**

```html
<script src="js/store/store.js"></script>
<script src="js/analytics/analytics.js"></script>
<script src="js/ui/ui.js"></script>
```

- **`type="module"` 금지.** `file://`에서는 CORS로 차단돼 화면이 백지가 되고, 콘솔 에러도 알아보기 어렵다
- 순서를 지킨다. `ui.js`가 마지막이다
- 파일이 아직 비어 있어도 된다. 빈 파일 3개를 만들어두면 404가 안 뜬다

## 책임

- 마크업, 스타일, DOM 렌더링, 이벤트 바인딩
- `Store` / `Analytics` 호출과 결과 표시
- 사용자에게 보이는 문구 — 에러 메시지 배치, 빈 목록 안내, 단위 표기

## 경계

- **localStorage를 직접 만지지 않는다.** 항상 `Store`를 거친다
- 검증을 직접 짜지 않는다. `Store.add()`가 돌려주는 `errors`를 화면에 뿌릴 뿐이다
  - `required`, `max`, `min` 속성은 넣어도 된다. 편의일 뿐 방어선이 아니다
  - `<input type="date" max="오늘">`을 넣되, 통과해도 `Store`가 다시 막는다
- 집계를 직접 계산하지 않는다. `Analytics`를 호출한다

`Store.add()` 반환값 처리:

```js
const r = Store.add(input);
if (!r.ok) { /* r.errors의 각 필드 옆에 메시지 표시 */ return; }
render();
```

## 필수 요건 (감점 직결)

- 목록은 **최신순**
- 저장된 활동이 0건이면 **안내 문구**를 띄운다 (빈 화면 금지)
- 삭제는 **확인 절차**를 거친다 — `confirm()`이면 충분하다
- 에러 메시지는 어느 필드가 잘못됐는지 알 수 있게 보여준다. `alert("입력 오류")` 한 줄은 부족하다

## 통계 화면

**차트 라이브러리를 쓰지 않는다.** CDN은 규정상 허용되지만:

- 행사장 네트워크가 끊기면 화면이 통째로 죽는다
- Chart.js 축·옵션 맞추는 데 30분이 날아간다

**CSS 막대로 그린다.** `div` 하나에 `width: {비율}%` 를 주면 끝이고 10분이면 된다.
월별 횟수·카테고리 분포는 가로 막대, 체중 추이는 숫자 목록 + 증감 표시로 충분하다.
시간이 남으면 그때 올린다.

표시할 것:
- `Analytics.summary()` → 총 활동 수, 총·평균 참여 인원, 총·평균 운동 시간
- `Analytics.monthlyCount()` → 월별 가로 막대
- `Analytics.byCategory()` → 카테고리별 가로 막대
- `Analytics.weightTrend()` → 날짜별 체중, 첫 값 대비 증감
- `Analytics.kcalBalance()` → 날짜별 섭취/소모/수지

**칼로리 소모는 추정치다.** 화면에 "운동 시간과 종목으로 추정한 값" 한 줄을 적는다.
값이 없는 날은 `0`이나 `NaN`이 아니라 `-` 로 표시한다.

## 샘플 데이터 버튼

- 누르기 전에 `confirm()` — 몇 건이 생기는지 알린다
- 자동 실행 금지. 페이지 로드 시 몰래 채우지 않는다
- 샘플 기록은 화면에서 구분되게 표시한다 (`memo`의 `[샘플]` 표시를 배지로 보여주면 된다)

## 하지 말 것

- `type="module"` 사용
- `localStorage` 직접 접근
- 검증 로직을 `ui.js`에 중복 구현
- 담당 폴더 밖 파일 수정 — `store.js`나 `analytics.js`가 안 돌아도 **직접 고치지 않는다.** 담당자에게 말한다
- 차트 라이브러리 도입 (필수 기능이 다 끝난 뒤가 아니면)
- 데모 시나리오에 없는 화면 만들기

## 검증 방법 (커밋 전 직접 확인)

크롬으로 `index.html`을 열고 손으로 확인한 뒤, 결과를 커밋 본문에 한 줄로 남긴다.

- 활동명 비우고 저장 → 막히고, **활동명 옆에** 메시지가 뜨는지
- 날짜를 내일로 → 막히는지
- 참여 인원 `0` / `-1` / `2.5` → 각각 막히는지
- 저장 → 목록 **맨 위**에 뜨는지
- 전부 삭제 → 빈 목록 안내 문구가 뜨는지
- 삭제 → 확인창이 뜨고, 취소하면 안 지워지는지
- 데이터 0건에서 통계 화면 → `NaN` / `Infinity` / 빈 막대가 안 보이는지
- 콘솔에 에러가 없는지

## 작업 순서

1. `index.html` 뼈대 + script 태그 3개 + 빈 js 파일 3개 → **커밋** (최우선, 10분)
2. 등록 폼 마크업 + `Store.add` 연결 + 에러 표시 → **커밋**
3. 목록 렌더링 (최신순, 빈 목록 안내) → **커밋**
4. 삭제 + 확인창 → **커밋**
5. `style.css` — 읽을 수 있는 수준까지만 → **커밋**
6. 통계 화면 (CSS 막대) → **커밋**
7. 샘플 데이터 버튼 → **커밋**

**1번이 늦으면 팀 전체가 멈춘다.** 다른 걸 먼저 하지 않는다.
2~4번(필수 기능)이 끝나기 전에는 5~7번에 손대지 않는다.
